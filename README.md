# Vivid Mistress

A lightweight, self-hosted single-chat web server with voice (TTS), role-playing personalities, and hands-free auto-continue. One Go binary, no Node.js, no Docker, no Python.

Optimized for the **Raspberry Pi** (ARMv6/ARM64) but builds for Windows, macOS, Linux, and FreeBSD.

---

## Features

- **Single Always-On Chat** — One persistent conversation per browser, no sidebar or account management.
- **Voice (Narrator Mode)** — Replies are spoken aloud via Microsoft Edge's online TTS. Choose from 36 voices (British, American, Australian, Japanese, Indian, and more) and adjust speed 1–9.
- **Role-Playing Personalities** — Load `.txt` role files from a `roles/` folder. Switch roles live by typing `role [n]`.
- **Auto-Continue ("Pushing")** — After a voice reply finishes, the chat automatically sends "continue" so the conversation keeps going hands-free. Configurable delay, stop/start, and a 3-push safety cap.
- **Microphone (Voice Input)** — Tap MIC to talk instead of typing (Web Speech API, Chrome). Hands-free mode auto-opens the mic after each voice reply. Needs HTTPS over LAN — see [Microphone](#microphone-voice-input) below.
- **Suggestion Buttons** — Up to 5 clickable reply buttons generated by the LLM. Adjust the count live with `buttons [n]`.
- **Text On/Off** — Hide the narration bubbles while keeping the voice and buttons (`text on` / `text off`).
- **Built-In Text Commands** — `help`, `status`, `role`, `voice`, `speed`, `delay`, `stop`, `start`, `buttons`, `text`, `clear` — all handled locally, never sent to the LLM.
- **Per-Browser Client ID** — Each browser gets its own isolated settings and conversation via a localStorage ID.
- **Zero External Runtime Dependencies** — Frontend (HTML/CSS/JS) embedded directly into the Go binary via `//go:embed`.
- **Flat-File JSON Persistence** — No CGO, no SQLite. Data stored as JSON files on disk.

## Build

### Local (current platform)

```bash
go build -o server .
```

### Cross-compile (from Windows/macOS/Linux)

```bash
# Raspberry Pi Zero W / Pi 1 (ARMv6)
GOOS=linux GOARCH=arm GOARM=6 CGO_ENABLED=0 go build -ldflags="-s -w" -o server ./cmd/server

# Raspberry Pi 3 / 4 (64-bit)
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -ldflags="-s -w" -o server ./cmd/server

# Windows x64
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-s -w" -o server.exe ./cmd/server
```

All 12 platform combinations are covered by the `executables/build_all.bat` and `executables/build_all.ps1` scripts.

## Run

```bash
./server -addr :8080 -data ./data -roles ./roles
```

| Flag       | Default     | Description                                          |
|------------|-------------|------------------------------------------------------|
| `-addr`    | `:8080`     | HTTP listen address                                  |
| `-data`    | `./data`    | Data directory for JSON storage                      |
| `-roles`   | `roles`     | Directory containing role `.txt` files               |
| `-model`   | `gemma4:31b` | Default Ollama model name                           |
| `-llm-dump`| *(empty)*   | If set, directory where raw LLM requests/responses are dumped |
| `-tls-addr`| `:8443`     | HTTPS listen address (phone mic over LAN). Empty = HTTP only |
| `-cert`    | `./cert.pem` | TLS cert file (auto-created if missing)                |
| `-key`     | `./key.pem`  | TLS key file (auto-created if missing)                 |

Open `http://localhost:8080` in a browser.

Just running `./server` with no flags starts **both**: HTTP on `:8080` and HTTPS on `:8443` (cert auto-generated on first run).

```
data/
├── providers.json                          # LLM backend endpoints (shared)
└── clients/
    └── <client-id>/
        ├── settings.json                   # Per-browser app settings
        ├── system_prompts.json             # Named system prompts
        └── conversations/
            └── <conversation-id>.json      # One file per chat thread
```

A default Ollama provider pointing at `https://api.ollama.com` is created on first run with an empty API key — add your key to `data/providers.json` for online Ollama, or point `base_url` at a local instance (no key needed).

## Chat Commands

Type these directly in the chat. They are handled locally and never sent to the LLM.

| Command         | Description                                                  |
|-----------------|--------------------------------------------------------------|
| `help`          | Show the command list                                        |
| `status`        | Show current voice, role, speed, delay, buttons, listen     |
| `role`          | List available roles                                         |
| `role [n]`      | Switch to that role (e.g. `role 2`)                          |
| `voice`         | List available voices                                        |
| `voice [n]`     | Switch to that voice (e.g. `voice 5`)                        |
| `speed [n]`     | Set voice speed 1–9 (3 = 1.3x, 5 = 1.5x; default 3)         |
| `delay [n]`     | Pause after voice reply before pushing "continue" (seconds)  |
| `stop`          | Stop auto-mic + auto-pushing messages                        |
| `start`         | Start hands-free: auto-mic opens after each voice reply      |
| `buttons [n]`   | Set suggestion buttons per reply, 1–5 (default 5)            |
| `listen`        | Toggle auto-mic: mic opens by itself after each voice reply  |
| `text on/off`   | Show or hide the narration text (voice + buttons unaffected) |
| `clear`         | Clear the conversation context (keeps your role)             |

## Microphone (Voice Input)

Tap the **MIC** button in the composer to talk instead of typing. Uses the browser's built-in Web Speech API (Chrome desktop + Android Chrome) — no app install, no API key. The transcript drops into the chat box and auto-sends. Hands-free mode opens the mic by itself ~1s after each voice reply ends (toggle with the `listen` command, `start`/`stop` control everything).

> **Browser support:** Chrome / Edge only. Firefox and Safari do not support `SpeechRecognition` — the MIC button will be dimmed and tapping it shows a notice.

### Ports: which URL to open

The server listens on **two ports** (both start by default with plain `./server`):

| URL | Port | Protocol | Use |
|-----|------|----------|-----|
| `http://localhost:8080` | 8080 | HTTP | PC browser, normal chat (no mic over LAN) |
| `https://localhost:8443` | 8443 | HTTPS | PC mic test (accept the self-signed warning) |
| `https://<PC-LAN-IP>:8443` | 8443 | HTTPS | **Phone mic** — e.g. `https://192.168.1.200:8443` |

Match the scheme to the port: `http://` + `:8080`, `https://` + `:8443`. Mixing them gives *"sent an HTTP request to an HTTPS server"* (or a spin with no page).

### Why HTTPS is required

Chrome treats the mic as a secure-context feature: it only allows microphone / speech recognition on `https://` or `http://localhost`. A plain `http://192.168.x.x:8080` over the LAN is **blocked even with permission granted**, so the server auto-generates a self-signed cert (`cert.pem`/`key.pem`, gitignored) and serves HTTPS on `:8443`.

### Phone setup (Android Chrome)

1. Phone and PC on the **same Wi-Fi** (not mobile data).
2. Run `./server` (starts both ports), then on the phone open `https://<PC-LAN-IP>:8443`.
3. Chrome warns **"Your connection is not private"** (`NET::ERR_CERT_AUTHORITY_INVALID`) — normal for a self-signed cert. Tap **Advanced → Proceed (unsafe)**.
4. Tap **MIC → Allow** microphone. Speak a full sentence, then **pause** — the transcript auto-sends. Tap MIC again (STOP) to cancel.
5. Hands-free: tap MIC **once** (this gives Chrome the user gesture it requires), then the mic re-opens by itself after every reply. If you see *"Tap MIC once to enable hands-free"*, that's Chrome's autoplay/gesture rule, not an error.

### Finding your PC's LAN IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' }
```

### Firewall

Allow inbound TCP on `8443` (and `8080` for plain HTTP) or approve the Windows Firewall prompt for `server.exe`. If the PC page loads but the phone times out (`ERR_CONNECTION_TIMED_OUT` / `ERR_CONNECTION_REFUSED`), it is Wi-Fi/firewall, not the app.

### Fallback: treat HTTP as secure (no cert)

If you do not want HTTPS, on the **phone's** Chrome open `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, enable it, enter `http://<PC-LAN-IP>:8080`, relaunch Chrome, then use plain `http://<PC-LAN-IP>:8080`. Must be repeated per phone and can reset on Chrome updates — HTTPS above is recommended.

### Troubleshooting (match the exact message)

| Message | Meaning / fix |
|---------|---------------|
| *sent an HTTP request to an HTTPS server* | Opened `http://…:8443` — use `https://…:8443` (or `http://…:8080`) |
| Warning page, no Proceed | Wrong port (`https://…:8080`). Use `:8443` |
| *Mic needs HTTPS (or localhost)* (in chat) | Page is on plain `http://LAN-IP` — switch to the `https://…:8443` URL |
| *Mic blocked* (in chat) | Chrome site permission: lock icon in address bar → Permissions → Microphone → Allow, then reload |
| *Did not hear anything* | Speak after the button turns red/STOP, then pause |
| *Speech service needs internet* | Google recogniser unreachable — check connection |
| Button never goes red | Restart `server.exe` + hard-reload the page (Ctrl+F5 / phone Reload) so the new `app.js` loads; check console for `auto-mic skipped: …` |

## Roles

Roles are plain `.txt` files in the `roles/` directory. Each file's content becomes the system prompt for the LLM. The file name (without `.txt`) is the role name.

Example `roles/Default.txt`:
```
You are a friendly, lightly proactive companion...
```

Switch roles live with `role [n]` — the change takes effect on the next message.
